# Запуск стека для RAG-кейса — шпаргалка

**Стек:** Docker Desktop · ngrok · n8n (npx) · Qdrant (Docker)
**ОС:** Windows 11, n8n запускается через PowerShell (npx)

> **Кнопки запуска (в этой же папке):**
> - `Запуск n8n.bat` — обычный повседневный запуск n8n (без Docker/ngrok).
> - `Запуск RAG-стека.bat` — для этого кейса: делает всё по шагам ниже автоматически (Docker → Qdrant → ngrok → n8n с подхваченным адресом). Требует `docker` и `ngrok` в PATH.

> Главное правило порядка: **ngrok идёт ПЕРВЫМ** (он выдаёт публичный адрес), **n8n — ПОСЛЕ** (ему этот адрес нужен при запуске). Бесплатный адрес ngrok меняется при каждом перезапуске — поэтому связку ngrok → n8n повторяем каждый раз заново.

---

## 🔧 Разовая настройка (делается один раз)

1. Установлен **Docker Desktop** (AMD64) и обновлён WSL (`wsl --update`).
2. Привязан токен ngrok:
   ```powershell
   ngrok config add-authtoken ТВОЙ_ТОКЕН
   ```
3. Один раз создан контейнер Qdrant с именем (чтобы потом просто включать его):
   ```powershell
   docker run -d --name qdrant -p 6333:6333 -p 6334:6334 -v qdrant_storage:/qdrant/storage qdrant/qdrant
   ```
   (`-d` = работает в фоне, окно занимать не будет. `-v` = данные сохраняются между запусками.)

---

## ▶️ Каждый раз, когда садишься работать

### Шаг 0. Запусти Docker Desktop
Открой приложение Docker Desktop, дождись, пока значок кита перестанет мигать (Docker готов).

### Шаг 1. Включи Qdrant (фоном)
```powershell
docker start qdrant
```
Проверка: открой `http://localhost:6333/dashboard` — должна открыться панель.

### Шаг 2. Запусти ngrok (ОКНО PowerShell №1 — не закрывать)
```powershell
ngrok http 5678
```
Скопируй строку **Forwarding** — адрес вида `https://xxxx-xx-xx.ngrok-free.app`.

### Шаг 3. Запусти n8n с этим адресом (ОКНО PowerShell №2 — не закрывать)
Подставь свой ngrok-адрес из шага 2:
```powershell
$env:WEBHOOK_URL="https://xxxx-xx-xx.ngrok-free.app"
npx n8n
```

### Шаг 4. Проверь, что всё живо
| Что | Адрес | Что должно быть |
|-----|-------|-----------------|
| n8n локально | `http://localhost:5678` | открывается интерфейс n8n |
| n8n снаружи | твой `https://...ngrok-free.app` | та же n8n (значит, WEBHOOK_URL подхватился) |
| Qdrant | `http://localhost:6333/dashboard` | панель Qdrant |

Если все три открываются — стек готов, можно работать с воркфлоу. 🎉

---

## ⏹️ Когда закончила работать

- n8n: в окне №2 нажми `Ctrl + C`.
- ngrok: в окне №1 нажми `Ctrl + C`.
- Qdrant (по желанию, можно и оставить):
  ```powershell
  docker stop qdrant
  ```

Данные Qdrant **не потеряются** — они в томе `qdrant_storage`.

---

## 🆘 Если что-то не так

| Симптом | Причина / решение |
|---------|-------------------|
| Публичный чат-виджет не открывается снаружи | Не задан `WEBHOOK_URL`, или ngrok перезапускался и адрес сменился → перезапусти n8n с новым адресом |
| Docker не стартует, просит WSL | `wsl --update --web-download` из админ-PowerShell |
| `docker start qdrant` пишет «No such container» | Контейнер не создан — выполни команду из «Разовой настройки», п.3 |
| Qdrant-дашборд не открывается | Docker Desktop не запущен, или контейнер не включён (`docker start qdrant`) |
| n8n в нодах не видит Qdrant | URL должен быть `http://localhost:6333` (т.к. n8n через npx, а не в Docker) |
| Порт 5678 занят | Закрой старый процесс n8n или перезапусти PowerShell |

## Порядок одной строкой (шпаргалка-напоминалка)

```
Docker Desktop → docker start qdrant → ngrok http 5678 → (скопировать адрес) → $env:WEBHOOK_URL="адрес" → npx n8n
```
