# Кейс 11 — AI-консультант по базе знаний (RAG)

**Тема урока:** RAG, векторные базы, работа с документами
**Стек:** n8n + Qdrant (Docker) + OpenAI + веб-виджет + ngrok
**Уровень:** портфолио / коммерческий заказ

---

## 1. Что это за кейс и зачем он в резюме

Компания (магазин, агентство, инфобизнес — любая ниша) хочет бота, который отвечает клиентам **строго по своим материалам**: регламентам, FAQ, прайсу, условиям доставки. Обычный ChatGPT тут не подходит — он не знает внутренних данных и «придумывает». Решение — **RAG** (Retrieval-Augmented Generation): бот сначала *находит* нужные куски в базе знаний компании, а потом *на их основе* формулирует ответ.

Это один из самых частых платных заказов на фрилансе в 2025–2026. В резюме звучит так:

> Разработал AI-консультанта на базе n8n с RAG-архитектурой: индексация документов в векторную БД Qdrant, семантический поиск по эмбеддингам, генерация ответов через LLM с опорой только на данные клиента. Интеграция в сайт через встраиваемый чат-виджет.

---

## 2. Как работает RAG (держи это в голове при сборке)

RAG делится на **два независимых процесса**, поэтому и воркфлоу будет два.

**A. Индексация (делается один раз / при обновлении документов):**

```
Документы → разбивка на куски (chunks) → эмбеддинги → запись в Qdrant
```

Каждый кусок текста превращается в *вектор* — массив чисел, который кодирует смысл. Похожие по смыслу тексты дают близкие векторы. Всё это складывается в Qdrant.

**B. Ответ на вопрос (на каждый запрос пользователя):**

```
Вопрос → эмбеддинг вопроса → поиск похожих кусков в Qdrant → LLM(вопрос + найденные куски) → ответ
```

LLM получает вопрос **вместе с релевантным контекстом** и отвечает только по нему. Если в базе ответа нет — бот честно говорит, что не знает (это прописывается в системном промпте).

Ключевая мысль для собеседования: *эмбеддинг — это смысл в виде вектора; векторная база ищет по смыслу, а не по точному совпадению слов.*

## 3. Что включить перед стартом (чек-лист)

| # | Сервис | Команда / действие | Зачем |
|---|--------|--------------------|-------|
| 1 | **n8n** | запустить как обычно, `localhost:5678` | основной движок |
| 2 | **Qdrant** | `docker run -p 6333:6333 -v qdrant_storage:/qdrant/storage qdrant/qdrant` | векторная база |
| 3 | **OpenAI API-ключ** | проверить баланс на platform.openai.com | эмбеддинги + чат-модель |
| 4 | **ngrok** | `ngrok http 5678` → скопировать `https://...` | публичный адрес для веб-виджета |
| 5 | **Документы** | папка с PDF/txt/Markdown (см. раздел 7) | то, по чему ищем |

> **Важно про ngrok и n8n.** Чтобы публичный чат работал, n8n должен знать свой внешний адрес. Запусти n8n с переменной окружения:
> `WEBHOOK_URL=https://твой-адрес.ngrok-free.app`
> (в Docker — через `-e WEBHOOK_URL=...`). Иначе виджет сгенерирует ссылку на `localhost`, и снаружи он не откроется.

> **Совет по Docker-сети.** Если n8n тоже в Docker, обращайся к Qdrant не по `localhost`, а по имени сервиса / `host.docker.internal:6333`. Если n8n локально (npx/десктоп), а Qdrant в Docker — подойдёт `http://localhost:6333`.

## 4. Воркфлоу №1 — Индексация документов

Цель: загрузить документы компании в Qdrant. Запускается вручную (или по расписанию при обновлении базы).

**Ноды по порядку:**

1. **Manual Trigger** — «When clicking Test workflow». На старте этого хватит.

2. **Источник документов.** Выбери под свой кейс:
   - *Read/Write Files from Disk* (режим Read) — читает файлы из папки на диске;
   - либо *Google Drive* → Download;
   - либо HTTP Request, если документы по URL.

3. **Qdrant Vector Store** — режим **Insert Documents** (Add documents to vector store).
   Настройки:
   - **Qdrant Collection:** `company_kb` (создастся автоматически, если включить опцию, или создай заранее).
   - **Credential:** Qdrant API — URL `http://localhost:6333` (или `host.docker.internal`), ключ можно оставить пустым для локального.

   К этой ноде подключаются под-ноды (значки снизу):

4. **Embeddings OpenAI** (подключается к Qdrant как Embedding):
   - Model: `text-embedding-3-small` (дёшево и качественно).
   - Credential: твой OpenAI ключ.

5. **Default Data Loader** (подключается к Qdrant как Document):
   - Type of Data: *Binary* (если читаешь файлы) или *JSON*.
   - **Text Splitting:** переключи на **Custom** — только тогда появится возможность подцепить свой сплиттер. (Если оставить *Simple* — n8n порежет текст сам, для маленьких документов этого достаточно, и шаг 6 можно пропустить.)

6. **Recursive Character Text Splitter** — подключается **к Data Loader, а не к Qdrant!** Вложенность такая:
   ```
   Qdrant → Document → Default Data Loader → Text Splitter → Recursive Character Text Splitter
   ```
   После того как в Data Loader выбрал Text Splitting = Custom, под нодой Data Loader появится коннектор **«+ Text Splitter»** — нажми его и выбери Recursive Character Text Splitter:
   - Chunk Size: `1000`
   - Chunk Overlap: `150`
   (Это и есть «разбивка на куски» из теории. Overlap нужен, чтобы мысль не обрывалась на границе кусков.)

**Проверка:** запусти воркфлоу → зайди на `http://localhost:6333/dashboard` → должна появиться коллекция `company_kb` с точками (points). Это твои векторы.

## 5. Воркфлоу №2 — Ответ на вопрос (RAG + веб-виджет)

Цель: принять вопрос с сайта и ответить по базе знаний.

**Ноды по порядку:**

1. **Chat Trigger** (`When chat message received`):
   - **Make Chat Publicly Available:** включить.
   - **Mode:** Embedded / Hosted Chat.
   - После сохранения n8n даст ссылку и `<script>`-код для вставки на сайт. Благодаря `WEBHOOK_URL` (ngrok) ссылка будет публичной.

2. **AI Agent** (или **Question and Answer Chain**). Рекомендую **AI Agent** — гибче и эффектнее в портфолио:
   - **System Message** (важная часть!):
     ```
     Ты — консультант компании. Отвечай ТОЛЬКО на основе данных,
     полученных из инструмента поиска по базе знаний. Если ответа
     в базе нет — скажи, что уточнишь у менеджера, и не выдумывай.
     Отвечай кратко, по-деловому, на русском.
     ```

   Под-ноды агента:

3. **OpenAI Chat Model** (как Chat Model):
   - Model: `gpt-4o-mini` (баланс цены/качества) или `gpt-4o`.

4. **Vector Store Tool** (как Tool) — даёт агенту инструмент «искать в базе»:
   - Name: `knowledge_base`
   - Description: `Поиск по регламентам, FAQ и прайсу компании`
   - Внутри подключается:

5. **Qdrant Vector Store** — режим **Retrieve Documents** (как Tool):
   - Collection: `company_kb` (та же, что в воркфлоу №1!).
   - Limit: `4` (сколько кусков доставать).

6. **Embeddings OpenAI** (как Embedding к Qdrant) — **обязательно та же модель**, что при индексации: `text-embedding-3-small`. Если модели разные — поиск не сработает.

7. **Simple Memory** (Window Buffer Memory, как Memory к агенту) — чтобы бот помнил контекст диалога.

**Схема связей агента:**
```
AI Agent
 ├─ Chat Model      → OpenAI Chat Model (gpt-4o-mini)
 ├─ Memory          → Simple Memory
 └─ Tool            → Vector Store Tool
                       └─ Qdrant (retrieve, company_kb)
                            └─ Embeddings OpenAI (text-embedding-3-small)
```

**Проверка:** открой публичную ссылку чата (или нажми Chat в n8n) → задай вопрос, ответ на который есть в документах → бот должен ответить по делу. Задай вопрос «не по теме» → должен отказаться выдумывать.

## 6. Типичные ошибки (пригодится на собеседовании)

- **Пустые ответы / бот ничего не находит** → разные модели эмбеддингов в индексации и в поиске. Должна быть одна и та же.
- **Виджет не открывается снаружи** → не задан `WEBHOOK_URL` или ngrok-туннель закрылся (бесплатный адрес меняется при перезапуске).
- **n8n в Docker не видит Qdrant** → используешь `localhost` вместо `host.docker.internal` / имени сервиса.
- **Бот «галлюцинирует»** → слабый system message; явно запрети отвечать без контекста из базы.
- **Куски слишком большие/маленькие** → крути Chunk Size: большие куски = меньше точности поиска, маленькие = теряется смысл.
